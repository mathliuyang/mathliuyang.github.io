EVENT 01 / CHINESE DRAFT

中文稿定稿

进入英文阶段前：内容与格式稳定

英文论文原则上应先完成中文内容和整体格式定稿，再开展英文翻译工作。中文稿件定稿时，应重点完成以下内容：

线上准备

完成中文母稿

定内容、结构和格式，补齐公式、图表、引用及作者基金信息。

阶段确认

确认可以翻译

不缺图、表、公式和引用，不再进行大范围内容改动。

产出

中文定稿

一份内容稳定、信息完整、可以进入英文阶段的母稿。

01

确定论文内容

论文结构、技术内容和逻辑关系基本确定。

02

完成整体排版

Word 或 LaTeX 排版格式基本完成。

03

补齐引用关系

公式、图、表和参考文献编号完整并采用交叉引用。

04

确认基础信息

作者、单位、基金项目和通信作者信息基本确定。

中文稿定稿清单8 项
  • 论文结构、技术内容和逻辑关系基本确定；
  • Word 或 LaTeX 排版格式基本完成；
  • 公式、图、表和参考文献编号完整；
  • 公式、图表和参考文献均采用交叉引用；
  • 所有图表均须在正文中进行引用和必要说明；
  • 若采用 Word 撰写，所有公式原则上统一使用 MathType 编辑；
  • 作者信息、作者单位、基金项目、通信作者信息等基本确定；
  • 检查是否存在缺图、缺表、缺公式、缺引用或编号错误等问题。
进入下一事件的门槛原则

在中文稿尚未稳定前，不宜过早开展大规模英文翻译，以免后续反复修改。

中文论文可参照本流程执行，并跳过中英文翻译环节。

EVENT 02 / OFFLINE MEETING

英文定稿会

线下逐字逐句：英文稿成为主版本

先在会前完成翻译和材料准备；线下由团队逐字逐句核对英文稿。首次投稿往往与本次会议连续完成。

线上准备

翻译并备齐材料

完成英文工作稿，同时准备中文稿、Cover Letter 和期刊要求。

线下会议

逐字逐句定稿

以英文稿为准核对技术含义、术语、表达、公式和图表引用。

产出

英文投稿稿

团队确认的英文主版本，以及待投稿的 Cover Letter 初稿。

会前 01

完成英文工作稿

忠实原意、自然表达，术语、方法、变量和缩写全文统一。

会前 02

备齐校稿材料

中文稿、英文稿、Cover Letter、期刊清单和必要信息全部到位。

线下 03

逐字逐句定稿

中文稿用于对照，最终以英文稿的逻辑和表达为准。

会后 04

AI 标注核查

只发现并标注语言和格式问题，不直接大改技术内容。

会前必须准备5 类材料

集中线下校稿前，至少准备以下材料：

  1. 中文稿；
  2. 英文稿；
  3. 中英文 Cover Letter 初稿；
  4. 期刊投稿要求或材料清单；
  5. 必要时准备作者信息、基金信息和投稿系统截图。
线下逐句校稿9 项

团队成员共同对英文稿进行逐字逐句核对。此阶段：

  • 中文稿主要作为内容对照和辅助理解；
  • 最终以英文稿的逻辑和表达为准；
  • 重点检查技术内容是否准确；
  • 检查英文是否存在歧义、漏译、错译或表达不自然；
  • 检查术语、缩写、符号和变量是否统一；
  • 检查公式、图表和参考文献引用是否正确；
  • 检查摘要、结论和创新点是否与正文一致；
  • 检查题目、作者、单位、基金和通信作者信息是否准确；
  • 检查图表标题、图例、坐标轴、单位和编号是否规范。

逐句校稿完成后，再使用 AI 对全文进行语法和格式核查。AI 的作用主要是发现问题并标注，不应在未经确认的情况下直接大幅修改技术内容。

Cover Letter 核查会前完成

集中校稿时，应同时讨论和完善 Cover Letter 的中英文版本。最终提交前，重点检查：

  • 论文标题是否与稿件一致；
  • 期刊名称是否正确；
  • 是否误保留其他论文或其他期刊的信息；
  • 作者和通信作者信息是否准确；
  • 创新点是否表述清楚；
  • 日期和称谓是否规范。
英文稿件翻译原则9 项

在中文内容基本定稿后，将中文稿翻译为对应英文稿。翻译过程中应遵循以下原则：

  • 不随意改变原文含义、技术结论和逻辑关系；
  • 表达清晰、准确、通俗易懂，同时保持必要的学术性；
  • 避免使用生僻、冗长或刻意复杂的词汇和句式；
  • 优先采用计算数学、计算物理及相关国际期刊中的常用表达；
  • 参考 CMAME、JCP 等期刊的语言风格；
  • 采用 PINN、深度学习求解微分方程和 AI for Science 等领域的规范术语；
  • 同一专业术语、方法名称、变量名称和缩写应全文统一；
  • 不应仅进行逐字直译，应保证英文句子的逻辑、语法和阅读习惯自然；
  • 翻译过程中发现中文原稿表述不清时，应先核实原意，再进行英文表达。

英文稿形成后，后续校稿和投稿原则上以英文版本为准，中文版本主要用于对照和辅助讨论。

EVENT 03 / OFFLINE SUBMISSION

正式投稿会

线下共同完成：生成稿确认后再提交

正式投稿通常与英文定稿会在同一次线下连续完成。目标期刊、投稿系统和必填信息必须提前准备，会议现场用于最终确认，而不是临时查要求。

线上准备

预录投稿系统

走通流程，提前填写作者、基金和声明，准备全部上传文件。

线下会议

共同上传并提交

确认唯一终稿，检查系统生成 PDF，无误后向刘老师确认并提交。

产出

投稿记录与归档包

保存全部上传文件、系统最终稿和提交记录，并完成邮件、微信汇报。

会前 01

走通期刊与系统

提前核查要求并录入标题、作者、基金、声明等信息。

线下 02

定稿 Cover Letter

集中确认研究工作、创新价值、期刊匹配和作者声明。

线下 03

上传并检查 PDF

共同检查页面、公式、图表、符号、顺序和全部附件。

会后 04

提交归档与汇报

向刘老师确认后提交，归档包发邮件，最终 PDF 发微信。

提前熟悉目标期刊10 项

若已经明确目标投稿期刊，应提前熟悉该期刊的投稿要求和投稿系统，不要等到正式投稿时再临时处理。重点核查以下内容：

  • 期刊投稿范围及论文类型；
  • 稿件格式和模板要求；
  • 参考文献格式；
  • 图表格式、分辨率及文件类型；
  • 是否需要 Highlights、Graphical Abstract、Declaration、Data Availability Statement 等材料；
  • Cover Letter 要求；
  • 作者贡献声明、利益冲突声明及基金信息要求；
  • 是否需要推荐或回避审稿人；
  • 是否需要单独上传匿名稿、标题页、源文件或补充材料；
  • 投稿系统中的作者顺序、单位、基金和通信作者设置方式。
提前走通投稿流程11 项

正式投稿前，应尽可能提前进入投稿系统，将整个流程完整走一遍。可提前完成的内容应尽量提前填写，包括：

  • 论文标题；
  • 摘要；
  • 关键词；
  • 作者姓名及顺序；
  • 作者邮箱和单位；
  • 通信作者信息；
  • 基金项目；
  • 论文类型；
  • 研究领域分类；
  • 推荐或回避审稿人；
  • 各类声明和问答。

暂未定稿的稿件、Cover Letter 或其他上传材料，可先使用明确标记的占位文件完成流程测试，正式提交前再统一替换。

特别注意：作者信息、基金信息和单位信息应提前核对并填写准确，避免正式投稿时现场补充，影响投稿效率或产生错误。

Cover Letter 编写流程完整要求

Cover Letter 应采用团队统一模板。开头、结尾、作者声明和整体结构原则上保持固定，仅根据不同论文修改具体内容。Cover Letter 通常包括：

  • 稿件标题；
  • 投稿期刊名称；
  • 研究背景和问题；
  • 论文的主要工作；
  • 主要创新点及学术价值；
  • 稿件与目标期刊范围的契合性；
  • 稿件未一稿多投、未重复发表等声明；
  • 全体作者同意投稿的声明；
  • 通信作者信息。

Cover Letter 的核心内容应与论文摘要、引言和结论保持一致，不得夸大创新性，也不应写入论文中无法支持的结论。

最终提交前，重点检查论文标题、期刊名称、作者与通信作者信息、创新点、日期和称谓，并确认未误保留其他论文或其他期刊的信息。

投稿前最终检查10 项

正式上传前，应完成以下检查：

  • 确认上传的是最终版本；
  • 确认文件名清晰、规范；
  • 确认未误传旧版本、带批注版本或内部讨论版本；
  • 确认作者顺序与稿件一致；
  • 确认基金、单位和通信作者信息正确；
  • 确认 Cover Letter 中的论文标题和期刊名称正确；
  • 确认所有附件完整；
  • 确认稿件中不存在修订痕迹、批注或隐藏内容；
  • 确认图表清晰，公式、编号和交叉引用正常；
  • 确认投稿系统中的摘要、关键词等内容与稿件一致。
系统生成 PDF 集体确认8 项

所有文件上传并完成信息填写后，应生成投稿系统的最终 PDF 或预览版本。正式点击提交前，由团队成员共同检查最终生成文件，重点确认：

  • 页面是否完整；
  • 公式是否乱码；
  • 图表是否缺失、模糊或错位；
  • 特殊符号是否正确；
  • 作者信息是否正确；
  • 文件顺序是否正确；
  • 补充材料是否完整；
  • 是否误上传占位文件或旧版本。

确认无误后再正式提交。

投稿后归档与汇报完整交付

正式投稿后，应建立专门文件夹进行归档。建议命名格式为：正式提交版_期刊简称或期刊名_提交日期。例如：正式提交版_JCP_20260801。

文件夹中应至少包括：

  • 投稿系统要求上传的全部文件；
  • 投稿系统最终生成的 PDF 或编译版本；

归档完成后，将文件夹压缩打包。邮件主题建议统一为：期刊名_正式提交版。邮件正文可包含：

  • 论文标题；
  • 投稿期刊；
  • 提交日期；
  • 稿件编号，如已生成；
  • 附件内容说明；
  • 其他需要说明的信息。

邮件附件为正式投稿归档压缩包。邮件发送完成后，再将最终稿件 PDF 单独发送给刘老师微信，方便查阅。PDF 版本选择原则：

  • 若投稿系统生成了最终 PDF，优先发送期刊系统生成版本；
  • 若投稿系统未生成 PDF，则发送正式上传的稿件 PDF；
  • 发送前再次确认不是旧版本或内部修改版本。
EVENT 04 / OFFLINE REVISION

返修定稿与投稿会

线下共同完成：每条意见闭环

返修内容先分工完成，线下会议集中核对修改稿与返修信；团队复核并向刘老师确认后，在同一次会议中完成系统提交。

线上准备

分工修改与逐条回复

整理双语意见，完成修改稿、返修信及新增图表或证据。

线下会议

返修定稿与提交

逐条核对回复、正文和页码行号，共同检查系统最终稿。

产出

本轮返修提交版

正文与返修信完全一致，按 R1、R2、R3 分轮次归档。

会前 01

整理意见与方案

保留全部原始意见，形成中英文对照并逐条确定修改方式。

会前 02

完成修改工作稿

准备修改稿、返修信、原稿、原始意见以及新增材料。

线下 03

逐条核对定稿

确认回答、修改内容、图表及页码行号与正文完全一致。

线下 04

生成稿确认与提交

共同检查系统最终 PDF，提交后按返修轮次归档和汇报。

整理审稿意见与修改方案14 项

收到返修意见后，首先将编辑和审稿人的全部意见整理为中英文对照版本，便于团队共同理解和讨论。整理时应：

  • 保留编辑和审稿人的原始编号；
  • 不得遗漏、合并或擅自改写审稿意见；
  • 对每条意见给出准确中文翻译；
  • 区分编辑意见、审稿人意见和格式要求；
  • 初步标记每条意见涉及的论文位置；
  • 对存在歧义的意见单独标注，集中讨论。

团队共同讨论每条意见的处理方式，包括：

  • 是否接受并修改；
  • 修改哪些内容；
  • 是否需要补充理论说明；
  • 是否需要增加数值实验；
  • 是否需要补充参考文献；
  • 是否需要调整图表；
  • 是否需要解释未修改的原因；
  • 由哪位成员负责具体修改。

原则上应逐条回应，不得遗漏审稿意见。

返修信编写要求完整要求

返修信采用团队统一模板。开头、结尾、致谢和整体格式保持一致，根据具体审稿意见修改回复内容。每条回复一般包括：

  • 审稿人原始意见；
  • 对审稿人的感谢；
  • 对问题的理解；
  • 采取的修改措施；
  • 必要的解释或论证；
  • 修改后的具体内容；
  • 修改位置，包括页码和行号。

若涉及图表新增或修改，应在返修信中插入对应图表或关键修改内容，便于审稿人直接核对。返修信中的回复应做到：

  • 态度客观、礼貌、专业；
  • 回应明确，不回避问题；
  • 修改内容与论文正文完全一致；
  • 页码和行号准确；
  • 不夸大、不争辩、不使用情绪化表达；
  • 对无法采纳的意见，应给出充分、客观的理由。
提交与归档核查9 项

返修内容完成后，应重点核对：

  • 每条审稿意见是否均已回复；
  • 返修信中所述修改是否真实体现在正文中；
  • 页码和行号是否与最终修改稿一致；
  • 新增图表、公式和参考文献是否编号正确；
  • 修改稿是否保留了不应出现的批注或修订痕迹；
  • 是否需要同时上传清稿版和带修订版本；
  • 文件命名是否符合期刊要求；
  • 投稿系统中的作者、基金等信息是否需要更新；
  • 是否误上传旧版返修信或旧版修改稿。

上传完成并生成最终 PDF 后，应再次由团队共同检查，确认无误后提交。

返修线下讨论前准备6 类材料

返修线下讨论前，应准备：

  1. 修改稿中英文混排版本，便于对照修改；
  2. 返修信中英文混排版本；
  3. 必要时另附中英文分开的修改稿和返修信；
  4. 原始投稿稿件；
  5. 编辑和审稿人原始意见；
  6. 新增或修改的图表、数据和参考文献。

中英文可以采用混排或分开方式，核心原则是便于逐条对照、讨论和修改。

返修提交后完整归档11 类文件

返修提交后，按照正式投稿阶段的方式重新整理文件夹。

建议文件夹命名格式为：第1次返修提交版_期刊名_提交日期，或：R1提交版_期刊名_提交日期。若有多轮返修，可依次采用：

  • R1 提交版；
  • R2 提交版；
  • R3 提交版。

归档内容应包括：

  • 原始审稿意见；
  • 中英文审稿意见整理版；
  • 修改稿中文版本；
  • 修改稿英文版本；
  • 带修订版本；
  • 清稿版本；
  • 中英文返修信；
  • 新增或修改的图表及数据；
  • 投稿系统上传的全部材料；
  • 投稿系统最终生成的 PDF；
  • 提交成功记录。

归档压缩后发送至刘老师邮箱。邮件主题可采用：期刊名_R1返修提交版。邮件正文注明：

  • 论文标题；
  • 投稿期刊；
  • 返修轮次；
  • 提交日期；
  • 稿件编号；
  • 本轮主要修改内容；
  • 附件说明。

同时，将返修提交后的最终 PDF 单独发送至刘老师微信，方便查阅。

EVENT 05 / TRANSFER

转投准备与投稿

新期刊材料全部适配后再提交

转投不是直接换一个投稿入口。会前应准备新 Cover Letter、匹配新期刊模板与文件要求，并提前熟悉或录入新投稿系统的信息流程。

线上准备

适配新期刊

匹配新期刊样式逐项重查
  • 重新核查期刊投稿范围及论文类型；
  • 重新套用稿件格式和模板要求；
  • 更新参考文献格式；
  • 匹配图表格式、分辨率及文件类型；
  • 补齐 Highlights、Graphical Abstract、Declaration、Data Availability Statement 等材料；
  • 确认匿名稿、标题页、源文件、补充材料及作者贡献等要求；
  • 全文检查并删除上一期刊名称、模板、称谓和残留信息。
Cover Letter 重新适配不能沿用旧刊信息
  • 使用团队统一模板，重新填写稿件标题和新投稿期刊名称；
  • 针对新期刊重新说明研究背景、主要工作、创新点和学术价值；
  • 重新说明稿件与新期刊范围的契合性；
  • 保留未一稿多投、未重复发表及全体作者同意投稿的声明；
  • 核对通信作者、日期、称谓和作者信息；
  • 确认未保留上一期刊、其他论文或旧日期信息。
提前熟悉或录入系统提交前完成
  • 提前进入新投稿系统并走通整个流程；
  • 预先录入标题、摘要、关键词、作者、单位、基金和研究分类；
  • 预先准备推荐或回避审稿人、声明和问答；
  • 可用明确标记的占位文件测试，但正式提交前必须统一替换；
  • 上传后生成最终 PDF 或预览版本，由团队共同检查；
  • 按新一次正式投稿建立独立归档，不覆盖上一期刊材料；
  • 提交前由团队复核并向刘老师确认。

提交边界与出版方式原则

涉及技术内容、作者信息、基金信息或其他重要修改时，应在最终提交前向刘老师确认。

校样阶段原则上只处理排版、格式和编辑查询问题，不宜进行大规模技术内容修改。

涉及出版方式选择时，除非已提前明确需要开放获取，通常优先选择传统订阅出版方式，而不是开放获取方式。提交前应再次确认出版选项，避免误选并产生额外费用。

邮件发包，微信发 PDF

英文稿核查提示词

请对以下英文论文内容进行系统核查，并遵循以下要求：

1. 不改变原文的技术含义、研究结论和逻辑关系；
2. 重点检查语法、拼写、冠词、单复数、时态、主谓一致、介词和标点；
3. 检查是否存在中式英语、表达歧义、句子过长或逻辑不清的问题；
4. 检查专业术语、缩写、变量名称和方法名称是否前后一致；
5. 检查图、表、公式和参考文献的交叉引用是否规范；
6. 检查标题、摘要、关键词、正文和结论的表达风格是否统一；
7. 优先采用计算数学、计算物理、PINN、深度学习求解微分方程及 AI for Science 领域的常用表达；
8. 避免使用生僻词汇和过度复杂的句式；
9. 不要直接重写全文，请按“原文—问题说明—修改建议”的形式逐项标注；
10. 对可能涉及技术含义变化的修改，应明确标记为“需要作者确认”。
